## 一、背景与证据

任务地图(6 段:`目标 / 最新要求 / 近期需求 / 已做 / 结果 / 更早的需求`)自 09-15 引入后,
「短消息(≤15 字)→ LLM 轮次」中位数从 **5 轮 → 56 轮**(决定性单例:「现在重启了」5 字跑 56 轮 / 151 次工具调用)。
根因是**自我强化闭环**:模型自己的过程旁白 → `conclusions` 轨 → 地图「结果」段 → 锚 → 回喂模型自身。

P0-1/P0-3/P0-4/P0-6 做了多轮补丁(旁白降级、只读化、输出行剔除、提示去标签),
但**闭环的物理入口没被消除**:

- 「已做」段来源是 `ledger`(工具履历原文),它**不是**旁白,过滤规则治不到它;
  实测「已做」里出现 `- ⤷ [tool-result-trimmed] | [r4678] | exit=0 | 64: …` 这类原始输出回声。
- 「结果」段即使加了元叙述过滤,仍会保留"含结论关键词"的正文 → 仍能回喂自己。

**本轮现场自证(第二次)**:两次注入的锚里,「结果」段回喂的正是**上一轮我自己的分析文字**
(「1. 地图 6 段是压缩块 4 轨的投影,零新增信息;2. …」)。这是一手证据。

## 二、为什么选择「去掉」而非「继续打补丁」

1. **零新增信息**:6 段全是压缩块 4 轨(`demands/conclusions/explanations/ledger`)的**投影**,
   没有一丁点压缩块里没有的信息。
2. **闭环入口在内**:「已做」来自 ledger(无法靠旁白规则根治);「结果」来自 conclusions。
   只要这两段存在,模型输出就有一条稳定回流路径。
3. **地图剩下的唯一真价值是「位置」** —— 把目标搬到**消息尾部**(注意力更强)。这用 **1 行**就能做到。
4. **「未完成什么」从来不归地图管**:待办的真实来源是 `TodoWrite` → 锚的 `### 下一步`
   (来源是 `TodoManager` 的 pending 项,有完成度判定)。地图的「更早的需求」冒充待办正是
   "重复劳动"的另一诱因(09-16 文档缺陷 2/3)。

## 三、方案 B:降级为「单行目标锚」

### 3.1 锚的最终形态

```
〔任务锚〕按下面清单继续推进;需要更早的历史原文时,用 ContextRecall(seq=n) 回查压缩块中的 [r{n}] 行。
**会话目标:** <最初目标(demands[0])>          ← 唯一保留的地图残留,1 行
### 下一步                                     ← 真实未完成待办(存在时)
- <pending todo 1>
## 任务清单                                    ← TodoWrite 当前清单(存在时)
- [ ] …
```

去掉了:`## 任务地图` 标题、`**最新要求:**`、`### 近期需求`、`### 已做`、`### 结果`、`### 更早的需求`。

「最新要求」删除的理由:用户当轮消息**本来就在 tail 尾部**,重复它零增益。

### 3.2 「不迷失」的三条替代保证

| 担心的问题 | 新的保证 |
|---|---|
| 长会话忘了最初目标 | 单行 `**会话目标:**`(demands[0],首条免裁,始终在块内且在锚尾复述) |
| 忘了还剩什么没做 | `### 下一步` ← `TodoManager` 的 pending(有完成度判定,非历史需求) |
| 忘了历史细节 | `ContextRecall(seq=n)` 回查 `[r{n}]` 行(锚首句已给出入口) |

### 3.3 目标取值的取舍

- 取 `demands[0]`(最初目标),**不取末条**:末条就是用户当轮消息,已在 tail。
- 已知局限:若用户中途**切换主题**,首条目标会显得陈旧。缓解:
  - 措辞用中性「会话目标」而非「当前任务」,不宣称是待办;
  - 锚首句无未完成待办时仍走 `TASK_ANCHOR_HINT_IDLE`(纯声明式,禁止复述);
  - 「下一步」段只在**真有 pending** 时出现 —— 陈旧目标不会单独诱导继续干活。

## 四、实现要点(改了 2 处)

### 4.1 `src/agent/contextManager.ts`

- `residentMap: string[]` → `residentGoal: string`;
- `getResidentMap()` → `getResidentGoal(): string`;
- `seedResidentMap()` → `seedResidentGoal()`(从恢复块取 `demands[0]`);
- `buildResidentMap(parts, prevMap)` → `buildResidentGoal(parts): string`(只取 `demands[0]`);
- 删除 `RESIDENT_MAP_RECENT_DEMANDS`/`accumulateRecentDemands` 相关调用;
- `DEMAND_KEEP_TAIL`:原为「近期需求条数 + 1」,地图去掉后简化为**保护末条最新要求**的固定小值(2);
- `pickTrimVictim` 保留需求轨软保护(首条 + 末尾 K 条),语义不变。

### 4.2 `src/agent/agentLoop.ts`

- `buildTaskAnchor(todoBlock, goalLine?: string, pendingTodos?, modeNote?)`:
  `mapLines` → `goalLine`(单行,非空时输出 `**会话目标:** ${goalLine}`);
- `injectTodoIntoMessages` 的 `opts.mapLines` → `opts.goalLine`;
- 删除 `sanitizeMapLines` / `toReadOnlyMapLines` 调用与 `./taskMap` import;
- 锚不再有「只读化」分支(那是为地图措辞设计的;单行「会话目标」本身已是中性历史语义)。

### 4.3 删除

- `src/agent/taskMap.ts`(整文件)
- `tests/taskMap.test.ts`(整文件)

保留:`contextCompactor.ts` 的 `CompactBlockParts.map` 字段 —— 它仍用于**向后兼容解析旧块**
(旧会话的压缩块里可能带地图轨),只是不再写入。

## 五、影响面与验证

**设置项**:主键改为 `dsbAgent.compaction.goalAnchorEnabled`(语义更准),nls 描述同步更新。
**旧键 `dsbAgent.compaction.taskMapEnabled` 回退兼容**:0.4.0 已随版本发布该键,老用户若设过 `false`,
新版必须仍关闭目标锚 → `compactionGoalAnchorEnabled()` 读 `goalAnchorEnabled`,为空时回退读 `taskMapEnabled`(新键优先)。

**验证**:
- `npx tsc --noEmit` 干净;
- 全量 `npx vitest run` 全绿(地图相关用例改写为「目标锚」口径);
- 缓存前缀不回退:锚仍只走**消息尾部**,字节更短(去 5 段),不破坏任何前缀;
  跑 `python3 scripts/analyze-cache-prefix.py` 对比。

**回归口径**(长期):「短消息(≤15 字)中位轮次」应回落到 **≤10 轮**、`>60 轮占比` < 10%。
