# 设计:任务地图与需求轨保护(2026-09-14)

> 状态:✅ 已实施;对应扩展 0.3.0
> 关联:`taskMap.ts` / `contextManager.ts` / `contextCompactor.ts` / `agentLoop.ts`
> 计划:`.dsb/plans/2026-09-14-压缩目标漂移修复-plan.md`

## 一、设计目标

多轮对话经多次分轨压缩后,模型仍能稳定回答四个问题:
**目标是什么 / 干了什么 / 得到什么 / 下一步做什么**。即把「目标」从
「最先被丢弃、且离当前回合最远」的位置,搬到「永不裁剪、且每轮都能看见」的位置。

## 二、核心概念:任务地图(taskMap)

`src/agent/taskMap.ts` 是**纯函数、确定性**(同输入必同输出)——这一点是硬约束:
地图进入压缩块首段,块属消息前缀头部,字节必须跨轮稳定,否则缓存前缀断裂。

地图同时进入两处,职责不同:

| 落点 | 内容 | 作用 |
|---|---|---|
| **压缩块首段** | 常驻地图(永不参与裁剪) | 跨压缩保住目标,`lost-in-the-middle` 被绕开 |
| **每轮任务锚尾部** | 实时地图(带最新清单) | 工具执行轮也能看见目标/计划 |

### 五段结构(每段 ≤3 行,单行 ≤160 字符,超出 clip + 省略号)

```
## 任务地图
**目标:**      ← 「需求」轨首条(受保护,永不裁)
**最新要求:**  ← 「需求」轨末条(覆盖多轮澄清/修正,与目标相同则去重)
### 近期需求   ← 累积式(见下),中期澄清的常驻位
### 更早的需求   ← 需求轨较早的中间需求(取最近 2 条;**语义为历史需求,不宣称是待办**)
### 已做        ← ledger 轨最近 3 条(工具履历)
### 结果        ← conclusions 轨最近 3 条
```

> **三补(2026-09-15)**:地图**不再输出 `### 下一步`**。原因:压缩块访问不到 `TodoManager`,
> 用历史需求充当待办会把**已完成**事项显示为「下一步」→ 诱导模型重复劳动。
> 真实「下一步」由 agentLoop 的**任务锚**注入:`buildNextStepSection(pendingTodos)` 只接受
> `done=false` 的清单项,无未完成项时该段不输出。

## 三、三处关键设计

### 1. 需求轨保护(P0-a):`pickTrimVictim`
裁剪预算超限时不再「一律删最新 seq」,改为:
- 非需求轨(结论/说明/履历)→ 照旧按 seq 最新优先删(块尾先动,稳定段前缀字节不变);
- 需求轨 → **最后才动**,且**首条永不删**(最初目标),只删中间行。
- 两阶段收敛:① 软保护(首条 + 末尾 N 条免裁)→ 尽量保住中期澄清;② 仍超预算则放开软保护(仅首条免裁)→ 保证极端预算下块仍能收敛。

> 注:早期「首条 + 最近 3 条」保护过强,导致极小预算用例无法收敛,已回退为「软保护可放开、首条硬保护」。

### 2. 累积式「近期需求」(B4/B5)
问题:中期「目标澄清/修正」落在需求轨中间——既非首条(目标)也非末条(最新要求),
纯滑动窗口会被后续新需求挤出而永久消失。

解法:
```
extractMapSectionItems(prevMap, "近期需求")  // 取上一轮地图已有条目
  → accumulateRecentDemands(prev, candidates, max)  // 合并去重,只留最近 max 条
  → buildResidentMap(parts, prevMap)  // 重建地图
```
**语义:条目一旦进入地图即「粘住」**,直到被更新的 max 条挤出。地图永不参与裁剪
(块内常驻),所以这是「中期澄清不被压缩删掉」的最后一道保险。确定性保证字节稳定。

### 3. 运行时合成文本不入语义轨(第九轮修复)
根因:`maxTokensContinue` 注入的续写提示以
`{ role:"user", content: kMaxTokensContinueUserText }` 落盘(`agentLoop.ts`),
而抽轨对**任意** user 文本都 `demands.push` → 续写提示进需求轨,
顶掉地图「最新要求/更早的需求」位,**反过来加剧目标语义污染**。

修法(`contextManager.ts`):
- `isRuntimeContinueMessage(msg)`:判 `[续写]` 前缀 → 入轨前跳过;
- `INTERRUPTED_ASSISTANT_TEXT`(`[输出中断]`)→ 不参与结论/解释轨;
- `isRuntimeSyntheticText(text)` → 重建地图时**剔除历史遗留**的污染条目
  (累积式会「粘住」旧条目,必须显式过滤)。

## 四、任务锚注入(P0-b)

`injectTodoIntoMessages(messages, todoBlock, { anchorOnToolResult, mapLines })`:
- 尾部是普通 user 字符串 → 并入其 content 前部;
- 尾部是 user block 数组(非 tool_result)→ 最前插入 text 块;
- 尾部是**含 tool_result 的 user** → 在同一 user 消息的 tool_result **之后**追加 text 块
  (**不新增独立 user 消息**,避免角色不交替导致 API 400);
- 尾部是 assistant / 空 → 不注入(原样返回);
- **绝不挂 system 后缀**(system 字节变化会让 tools + messages 前缀全 miss);
- 不修改入参数组(仅请求视图,不进持久历史)。
