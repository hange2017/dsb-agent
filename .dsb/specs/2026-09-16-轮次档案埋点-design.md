# 轮次档案(turn_summary)埋点 — 设计说明

> 生成时间:2026-09-16
> 状态:已实施(代码 + 单测 + 编译安装)
> 关联任务:t101–t108
> 相关文档:`.dsb/docs/2026-09-16-agent效果评估基线.md`(效果评估基线)

## 1. 背景与动机

用户要在**其它项目**上用本扩展做真实任务,回头再统计「Agent 工作效果」。评估需要回答:

| 要回答的问题 | 旧数据能否直接答 | 缺口 |
|---|---|---|
| 一次大任务里执行了多少小任务 | ❌ | stats 侧**没有「工具调用总数」**(`tool_repeat` 只在**重复时**落一条);也没有轮次级事件 |
| 小任务是否在重复 | ⚠️ 半 | 有分子(`tool_repeat`),**没有分母**(总调用数)→ 算不出重复率 |
| 是否卡住 | ❌ | 没有终态原因(maxRounds / aborted / error)与耗时 |
| 缓存是否异常 | ⚠️ 半 | 有 `provider_round` 逐轮 usage,但**没有按轮聚合**的命中率 |

这些数字原本散落在会话 jsonl(VS Code `globalStorage/.../sessions/s_*.jsonl`,
按 `kind:"user"` 切段)里,事后重算**慢、易错、无项目维度聚合**。

**结论**:需要一个「轮次档案」事件,把一次大任务(一次 send)的散落计数在收尾时
一次落一条。

## 2. 口径(权威,禁止自造)

- **缓存命中率** = `cacheReadTokens / (cacheReadTokens + inputTokens)`,
  与 `scripts/analyze-cache-prefix.py` 头部注释的口径**完全一致**。
  分母为 0(无 usage)时**返回 undefined**,不用 0% 误导。
- **重复判定**由 `ToolRepeatTracker` 提供,与离线脚本 `analyze-duplicate-work.py` 同口径;
  重复率分子用「浪费型」重复(`isWaste`,间隔 < `wasteGapMs`),排除「改完再看」这类合理复查。
- **大任务定义**:一次用户消息(一次 `send`)→ 收尾渲染,期间展开成 R 轮
  `provider.round` 与 N 次工具调用。

## 3. 事件结构

事件类型 `turn_summary`,落 `~/.dsb/stats/<projectKey>/events-YYYY-MM-DD.jsonl`。

字段(`src/agent/turnSummary.ts` 的 `TurnSummary`):

| 字段 | 含义 |
|---|---|
| `sessionId` / `turnIndex` | 会话归属;会话内第几次 send(1 基) |
| `userTextLen` | 用户消息长度(字符数,**不记内容**) |
| `durationMs` | 本轮耗时(send 入口 → 收尾) |
| `rounds` | 实际执行的 provider.round 数(小任务轮数) |
| `toolCalls` / `toolErrors` / `distinctTools` | 工具调用总数(**分母**)/ 失败数 / 不同工具种类数 |
| `toolRepeatCount` / `toolRepeatWasteCount` / `redundantTokens` | 重复命中 / 其中浪费型 / 累计冗余 token(与 `tool_repeat` 同口径) |
| `compactionCount` | 本轮内压缩发生次数 |
| `contextRecallCalls` | ContextRecall 调用次数(**信息丢失的直接计分板**) |
| `appends` | 交互式追加注入次数 |
| `inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens` | provider 真实 usage 的本轮合计 |
| `chatMs` | 交互(非压缩)轮次耗时合计 |
| `endReason` | `done` / `error` / `aborted` / `maxRounds` |

派生命中率与重复率在**落盘侧**计算后一并写入(便于离线脚本直接读,不必二次换算):
`cacheHitRate`(4 位小数)、`repeatWasteRate`(4 位小数);为 undefined 时不写该字段。

## 4. 实现与接入点

| 位置 | 作用 |
|---|---|
| `src/agent/turnSummary.ts` | `TurnSummaryStats` 累加器(纯 TS,无 vscode 依赖,可单测)+ `cacheHitRate` / `repeatWasteRate` |
| `src/agent/agentLoop.ts` | `run()` 入口 `begin(sessionId, userTextLen, Date.now())`;过程中 `recordChatRound` / `recordTool` / `recordRepeat` / `recordCompaction` / `recordContextRecall` / `recordAppend`;收尾 `finish(endReason, Date.now())` → `deps.onTurnSummary?.(…)` |
| `src/chat/chatViewProvider.ts` | 订阅 `onTurnSummary` → `statsStore.record("turn_summary", {…, cacheHitRate, repeatWasteRate})` |
| `src/chat/chatController.ts` | `message_sent` 补 `sessionId`(首轮会话尚未 ensure 时取不到,由 `turn_summary` 提供完整归属) |
| `src/stats/statsStore.ts` + `configuration.ts` + `package.json` | 保留期可配置 `dsbAgent.stats.retentionDays`(默认 **365**,`0` = 永久保留) |

### endReason 判定

```
signal.aborted                                    → "aborted"
terminal.type === "done"                          → "done"
terminal.type === "error" 且 message 含
  "Exceeded max tool rounds"                      → "maxRounds"
其它 error                                        → "error"
无 terminal                                       → "aborted"
```

`finish()` **幂等**:重复调用时 `endedAt` 与 `endReason` 均以**首次**为准;
`durationMs` 取 `max(0, endedAt - startedAt)`,绝不产生负数。

## 5. 硬约束(遵守项目规则)

- **纯旁路**:`TurnSummaryStats` 不进入任何发给 provider 的载荷 —— 不触碰
  system prompt / 压缩块 / tail / messages 的字节,故**不影响缓存前缀稳定性**。
- **只记数字**:不落消息内容,隐私友好(与既有 stats 事件一致)。
- **fail-open**:打点失败绝不影响收尾(`try/catch` 包裹)。
- 引擎层(`src/` 非 webview)不依赖 `vscode` 模块,`turnSummary.ts` 因此可纯单测。

## 7. 已知边界 / 后续

- `turnIndex` 由 `TurnSummaryStats` **进程内**自增(扩展宿主进程内跨 send 保留);
  重载 VS Code 后从 1 重新计数 —— 跨会话统计请以 `sessionId` 分组,不要依赖 turnIndex 全局唯一。
- 命中率是**轮内合计口径**(整轮所有 provider.round 加总),用于趋势对比;
  逐轮明细仍看 `provider_round` 事件。
- 保留期默认从 30 天提到 365 天:老用户 30 天前的样本可能**已被旧版本清掉,无法找回**;
  本改动只保证**今后**不再被清。
