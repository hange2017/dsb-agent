# 压缩预算默认值调整(2026-09-19)

> 用户诉求:默认参数不适合日常场景 —— 历史信息预算过大、tail 占比过小。
> 主张「完成任务主要靠最近的信息,历史只需概括」,要求把预算与比例改为**近期优先**的默认值。
> 本文件记录**改动前的旧值、改动后的新值、代码落点、影响与待观察项**。

## 一、诉求

1. **历史信息总预算**:30000 token(原 64000)。96k 预算实测每轮成本 +45.8%(effIdx)/ +62.9%($),
   主因 `tail ×2.15`(见记忆 `dsb-agent-budget-96k-baseline`),故下调到 30000。
2. **三段比例**:压缩块 20% / thinking 0% / tail 80%(原 45% / 20% / 35%)。
   - 依据:完成任务是由**最近的信息**支撑的;历史信息以**概括**为足。
3. **thinking 推理脉络段**:0%(默认关闭思考编排)。
4. **触发比例**:85%(原 75%)—— 即当期 context 用到额定 85% 才触发压缩。
5. **压缩后目标比例**:50%(不变)。
6. **思考编排默认关闭**(不变,已是 `false`)。

## 二、默认值对照表

| 配置键 | 旧默认 | 新默认 | 语义 |
|---|---|---|---|
| `dsbAgent.compaction.historyTokenBudget` | 64000 | **30000** | 历史信息 token 总预算;0 = 关闭分轨预算 |
| `dsbAgent.compaction.budgetSplit.compacted` | 0.45 | **0.20** | 压缩块占历史预算比例 |
| `dsbAgent.compaction.budgetSplit.thinking` | 0.20 | **0** | 思考脉络轨比例(0 = 关闭该轨) |
| `dsbAgent.compaction.budgetSplit.tail` | 0.35 | **0.80** | tail(最近原文)占历史预算比例 |
| `dsbAgent.compaction.triggerPct` | 0.75 | **0.85** | 达到额定该比例才触发压缩 |
| `dsbAgent.compaction.targetPct` | 0.50 | 0.50(不变) | 压缩后收缩到额定的该比例 |
| `dsbAgent.compaction.thinking` | false | false(不变) | 思考编排总开关 |

> `thinking = 0` 时三段退化为两段:`applyThinkingToSplit` 把 thinking 的份额按比例回收,
> 归一化后即 **compacted 20% / tail 80%**(与用户要求的 3/7 之外的 2/8 口径一致)。

## 三、代码落点

| 文件 | 改动 |
|---|---|
| `package.json` | 4 处 `default`:`historyTokenBudget` 64000→30000;`budgetSplit` 0.45/0.2/0.35→0.2/0/0.8;`triggerPct` 0.75→0.85 |
| `src/settings/configuration.ts` | ①`historyTokenBudget()` 缺省/非法回退 64000→**30000**;②`kDefaultBudgetSplit` 0.45/0.2/0.35→**0.2/0/0.8**;③`compactionTriggerPct()` 缺省 0.75→**0.85**(注释同步) |
| `src/settings/agentSettingsPanel.ts` | `normalizeConfig` 默认值(设置面板 Webview 侧口径)同步:`budget: 30000`、`split: {compacted: 0.2, thinking: 0, tail: 0.8}`、`triggerPct: 0.85`、`targetPct: 0.5` |

> 四层默认值必须**同时**改,否则会出现「面板显示新值、实际生效旧值」的分裂:
> `package.json`(VS Code 设置默认)→ `configuration.ts`(读取端回退)→ `agentSettingsPanel.ts`(面板归一化)。

## 四、影响

1. **成本**:历史预算 64000 → 30000,单轮注入的历史部分减半;tail 占比 0.35 → 0.80,
   最近原文保留更多、压缩块更短。「历史摘要化」与用户「靠最近信息干活」的直觉一致。
2. **压缩频率**:`triggerPct` 0.75 → 0.85 → **更晚才触发压缩**,即单次注入的历史量更大,
   但压缩次数更少(每轮 token 上升、总轮次可能下降)。
3. **目标保全**:依赖需求轨(compacted 段)。compacted 由 45% 降到 20% →
   **块内可容纳的需求行更少**;中期「目标澄清」更依赖
   `dsb-agent-goal-drift-fix` 的三重保险(需求轨最新条 + 累积近期需求 + 需求轨不可全删)。
4. **可观测**:改动时间点已记入记忆(见下),用于后续统计对比。
