# 会话计划锚:冲突与复述修复(2026-09-19,第 7 轮)

> 前情:`.dsb/docs/2026-09-16-任务锚复述闭环根因与修复.md`(P0-6 去标签/de-命令句)、
> 本轮因地图降级后又把「未完成清单」放回锚里(v4:〔任务锚〕+`### 下一步`+`## 任务清单`)而复发。

## 一、现象(用户现场反馈,同一会话内可复现)

1. **待办被冻结在「等用户确认」**:地图「下一步」长期停在「让用户确认清单 / 等待用户确认」
   这类条目上(用户描述的大意);模型每轮都在**重新清点清单**。
2. **反复澄清、反复复述**:用户连续多轮反馈 agent 反复要求确认清单/复述计划,
   最后明确要求:**不要一遍遍让用户确认与复述,直接干活**。
3. **锚被读成汇报语域**:工具执行轮里,锚的「下一步/清单」被当成**对外汇报**的素材 ——
   表现为先把清单再列一遍、再问用户是否照此推进,而不是接着执行下一步动作。
4. 典型表现:**干一步、报一句、等一句**,而不是连续推进。

## 二、根因(4 条)

| # | 根因 | 机制 |
|---|---|---|
| A | **锚里是命令句,却没有优先级声明** | v4 `activeHint` = 「按下面清单继续推进…」。清单是**注入文本**,不是用户发言;模型把它当成「用户要求的事」,于是「完成清单」= 汇报到位,并倾向请用户确认后才划掉 |
| B | 段标题叫 **`### 下一步`** | 「下一步」是**汇报语域**的固定词位,天然诱发「下一步我打算…」的对外表述与「请确认下一步」 |
| C | **工具轮没有「当前用户消息」作边界** | 尾部是 `tool_result` 时锚只能追加在同一条 user 消息内,模型看到一个「看起来像需求」的长文本块,没有东西压住它 |
| D | 清单**长期无变更**且无「已做完」出口 | 待办恒为 pending → 锚每轮都在要「继续推进」→ 死循环清点。用户中止任务后尤其明显(用户要求停,锚还在催) |

> 与 P0-6 同源:**命令句 + 可引用名词(标签)= 复述发动机**。第 7 轮把 v4 的
> 「按清单继续推进」又写回来了,属旧病复发 —— 这也是本次要回到「声明式」的原因。

## 三、修复(v5,已实施)

| 落点 | 改动 |
|---|---|
| `agentLoop.ts` | ①尾部锚标签 `〔任务锚〕` → **`〔会话计划〕`**(去掉易被引用的「任务/锚」名词;旧常量 `TASK_ANCHOR_TAG` 已随文案**内联**,不再单独导出);②显式优先级声明 **「用户消息优先于本清单」**;③命令句「按下面清单继续推进」**删除**,改为**事实陈述**「下列未完成项即本会话待办,供导航」,并用「清单是否需要修订用 `TodoWrite` 处理,**不必在回复中说明**」取代旧命令句的出口 |
| `agentLoop.ts` | ④段标题 `### 下一步` → **`### 未完成项`**(`NEXT_STEP_TITLE`,最多 3 条;去汇报语域);⑤**不再另写冲突条款** —— 冲突裁决由提示首句「用户消息优先于本清单」一次声明,避免段内二次求值(与 P0-6「不要求模型求值」同源);⑥**不写「已完成请划掉」这类行动指令**在锚里,改由 `TodoWrite` 描述承担(见下行) |
| `agentLoop.ts` | ⑦无未完成项时改用 `TASK_ANCHOR_HINT_IDLE`:「〔只读参考·历史上下文〕以下内容**不是待办**、无需在回复中说明或确认,直接回应本轮用户消息即可;不要自行继续历史任务。…」——纯声明式,且**不再自称「计划/锚」** |
| `tools/todoTool.ts` | `TodoWrite` 描述补「用户新指令使部分项失效或中止时,用 update/clear 修订清单使其与本轮任务一致(**修订不必向用户解释**)」,避免「先汇报再改」 |
| `contextCompactor.ts` | `RECALL_HINT_LINE` 文案同步为「**当前目标见会话计划**」;新增 `LEGACY_RECALL_HINT_LINE_V3`(「当前目标见任务锚」)由 `isRecallHintLine` 兼容 → **历史已落盘旧块仍被识别,字节恒定不破坏缓存前缀** |
| `tests/agentLoop.test.ts` | 新增 `P0-7` 用例(锁死:锚不含「任务锚」/「继续推进」、含「用户消息优先」与 `ContextRecall(seq=n)`、`NEXT_STEP_TITLE === "### 未完成项"`);扩展 `P0-3` 用例(空闲提示措辞) |
| `tests/contextCompactor.test.ts` | 「parse 跳过历史版本 hint 行」用例扩到 **v1/v2/v3**(v3 = `当前目标见任务锚`),锁死旧块兼容路径 |

**核心语义转向**:锚不是「该做什么」的**指令源**,而是「计划当前状态」的**只读快照**;
推进依据永远是**当前用户消息**,锚只在两者一致时起备忘作用。

## 五、残留风险与监控

1. **〔会话计划〕仍是被引用名词**:P0-6 实证「标签 → 复述」;本轮用「优先级声明」压住,
   效果待观察。下轮采样若见「会话计划显示…」类旁白抬头,考虑**彻底去标签**(只留正文首句)。
2. **锚体量上升**(清单 + 冲突条款 ≈ +150~250 字符/轮):仅出现在消息尾部,不破坏前缀缓存,
   但每轮成本 +α;若清单条数多,`maxTodoAnchorLines` 仍会截断。
3. **只能治「锚」这一层**:清单修订**完全依赖模型主动** `TodoWrite`(锚不再下命令,只陈述清单状态);
   若模型不写,清单会滞后于真实进度(D 根因的弱化版)。真兜底是**每轮结束由引擎比对**「清单 vs 实际工具调用」,尚未做。
