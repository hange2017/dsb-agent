# 重复工作基线报告（裁剪/压缩是否导致 agent 返工）

> 生成时间：2026-09-15
> 脚本：`scripts/analyze-duplicate-work.py`（只读分析，附 `--self-test`）
> 数据源：4 个会话事件流（18,010 次工具调用）+ `~/.dsb/stats` 统计事件流（10,936 轮 LLM 调用、1,334 次压缩）
> 目的：量化「工具输出被裁剪 + 激进压缩」带来的额外返工消耗，为策略调整提供基线。

---

## 一、结论速览

| 指标 | 数值 |
|---|---|
| 同参数重复调用 | 1,408 次（**7.82%**） |
| 其中「浪费型」（同任务内 <5min 重现） | 492 次（**2.73%**） |
| 冗余 token（估算） | **647,049** |
| 折算输入成本（1 元/百万 token） | ≈ **0.65 元** |
| ContextRecall 调用（信息丢失计分板） | 95 次（其中 **52 次空结果**） |
| 压缩次数 / 压缩密度 | 1,334 次 / **每 8.2 轮压一次** |
| **压缩后 5min 内重复率 vs 其余时间** | **9.62% vs 5.95%（1.62x）** |

**判读**：浪费型重复占 2.73%，绝对量不大，属「局部返工」而非「全局失控」。
但**压缩后重复率抬升 1.62 倍**，实测证实压缩/裁剪与返工存在正相关。

---

## 二、因果链（已验证，非推测）

1. `Read` 属 `KEEP_TOOLS`（`src/agent/toolResultPolicy.ts:122`）→ **永不被规则裁剪**。
2. 但压缩时，其输出被摘要成「工具履历」轨的**一行**（实测该轨 115~297 行，压缩块 ≈15k token）。
3. agent 丢失文件细节 → **整文件重读**（榜单中 `| 0 | 0` = `offset=0, limit=0`）。

> 即：**主要损耗来自压缩，而非 trim**。trim 只作用于 Bash/Grep/WebFetch
> （`bashHead:5 + bashTail:30` 裁掉头尾），例如 `git diff src/extension.ts | cat` 被重复执行 16 次。

**Read 独占 87% 的冗余 token**（561k / 647k），是唯一值得优先优化的大头。

## 五、ContextRecall 明细（信息丢失直接证据）

| mode | 次数 | 含义 |
|---|---|---|
| `index_empty` | 46 | **索引为空（压缩后回查不到，空手而归）** |
| `index_hit` | 26 | 索引命中 |
| `seq_hit` | 17 | 按 seq 命中原文 |
| `seq_miss` | 6 | seq 未命中 |

> `index_empty` 占 48%：**近半回查是无效的**——压缩后 agent 意识到信息缺失，
> 但回查索引已空。这是「压缩过激」最直接的症状。

## 六、后续方向（按性价比排序）

1. **头文件/文档类 Read 结果延长保留**：`.h`、`.dsb/specs/`、`.dsb/plans/`
   属高密度精读对象，被摘要成一行代价最高 → 可在压缩时为其保留更多原文行
   （或按扩展名加权，不参与「工具履历」轨的单行摘要）。
2. **`index_empty` 修复**：46 次空回查说明索引未覆盖压缩块本身 → 补索引可
   把「重读文件」转为「一次回查」。
3. **运行时埋点**：在 agentLoop 检测重复调用并打 stats 事件，长期跟踪回归。

## 七、复现方式

```bash
python3 scripts/analyze-duplicate-work.py --self-test   # 算法自检
python3 scripts/analyze-duplicate-work.py --top 20      # 完整报告
python3 scripts/analyze-duplicate-work.py --gap 1800    # 换窗口(30min)
python3 scripts/analyze-duplicate-work.py --json        # 机器可读
```

口径说明：
- 「同参数重复」：同会话内 `(工具, 规范化参数)` 重现；`Read` 精确到 `(path, offset, limit)`，
  避免把分段落读同一文件误判为重复。
- 「浪费型」：重复且间隔 < `--gap`（默认 300s）。
- 冗余 token 为粗估（CJK 1.5 字符/token），仅供量级参考。
