# 任务锚复述闭环:根因与修复(P0-6)

> 生成时间:2026-09-16
> 现场会话:`s_mso6ljzd_ifk9`(本机)
> 关联文档:`.dsb/docs/2026-09-16-任务地图放大子任务实证与修复.md`(P0-1/P0-3/P0-4/P0-5)

## 一、现象(用户报告 + 量化)

用户报告:一次大轮任务里,agent 十多次输出同一句话——
"任务锚无待办,但你这条是明确提问(70K 何时生效),我继续查完再答"。

对会话 JSONL 扫描(4125 条 assistant 文本)得到计数:

| 措辞 | 次数 |
|---|---|
| 无待办 | 118 |
| 明确提问 | 53 |
| 我继续查 | 48 |
| 查完再答 | 45 |

同一句式**连出 10 个 round**(seq 13775 → 13808),每个 round 各一次。

## 二、根因:三层叠加

### 层 1 — 锚每轮都注入
`agentLoop.ts` 的 `injectTodoIntoMessages` 调用点在 `for (let round = 0; ...)` **循环体内**,
故不是"每轮对话一次",而是**每个 LLM round 一次**。复述因此与 round 数同阶。

### 层 2 — IDLE 首句是「条件指令」(发动机)
旧文案:

> 〔任务锚〕当前没有未完成的待办;若本轮消息未给出明确指令,请只回应本条消息,不要自行继续历史任务。

「**若**本轮消息未给出明确指令」要求模型**每轮重新求值**;求完的结论,
模型倾向于写出来当"已确认"。本轮恰有明确指令(问 70K),于是每轮都写成
"锚说无待办,**但**本条有明确指令,所以我继续"。

对照有 pending 分支的 `TASK_ANCHOR_HINT`(「按下面清单继续推进」)——**无条件句**,
无需求值,复述显著更少。这解释了「无待办」118 次远超「任务锚」56 次。

### 层 3 — 元叙述回流为「结论」(闭环)
过程旁白/客套收尾出现在**终答轮**(无 tool_use)时,被 `classifyAssistantText`
判为结论 → 进 `conclusions` 轨 → 地图「结果」段 → 下轮任务锚回喂自身 → 语域强化。

回路:

```
我的正文 → assistant 消息 → 压缩判为结论 → conclusions 轨
        → 地图「结果/历史结论」段 → 下轮锚注入 → 我又读到 → 再写类似话
```

现场证据:地图「历史结论」里固化了上一轮的客套收尾
"需要精确核对某段行为时,我可以跑测试…要我做只读诊断…也随时说。"

> 注:t72/P0-1 补全 只修了「带 tool_use 的过程轮降级」,而**元叙述恰恰常出现在无 tool_use
> 的终答轮**,故仍会进结论轨 —— 这是 P0-6 要补的洞。

## 三、附带污染(同源,取材碎片)

锚「结果」段长期携带两类脏行(本轮仍在现场复现):

| 段 | 脏内容 | 来源 |
|---|---|---|
| 结果 | `\## 一句话` | `demoteInnerHeadings` 降级后的标题残骸 |
| 结果 | `\| 问题 \| 答案 \| \|---\|---\| …` | `clip()` 把表格换行压平成一行的表 |

## 四、修复(P0-6)

| 措施 | 落点 | 说明 |
|---|---|---|
| **A 文案声明式** | `agentLoop.ts` `TASK_ANCHOR_HINT_IDLE` | 去掉「若…请…」条件句,改为纯声明式并**显式禁止复述/确认本段**;语义等价,模型无需再求值 |
| **B 去标签** | 同上 | idle 文案不再自称「任务锚」。实证复述句几乎全部以标签开头("任务锚显示无待办"/"锚显示无待办"),标签是每轮递出的**可引用名词**;行动指令只保留在**有 pending** 分支,idle 退化为「只读参考·历史上下文」 |
| **C 取材过滤** | `taskMap.ts` `sanitizeMapLines` | 注入侧对「结果/历史结论」段剔除①**结构碎片**(降级标题/压平表格/代码围栏/水平线)②**元叙述**(我继续/查完再答/随时说/需要我/我可以…);只匹配旁白句式,实质结论(含数字/文件)不受影响 |

三者关系:**A 治发动机(层 2)**、**B 断引用把柄**、**C 防存量回流(层 3)**。
C 在注入侧生效,对**存量地图立即起作用**,且地图只走消息尾部锚、不参与压缩块前缀,
**过滤无缓存副作用**(符合缓存前缀稳定性规则)。

### 生效前提:必须「重载窗口」(不是重装)
扩展安装在**同一版本号**上原地覆盖目录,但已运行的扩展宿主(exthost)仍持旧 dist 于内存,
**不会**自动重新加载。实测(2026-09-16):exthost 启动于 13:07:18,而 0.4.0 目录在 13:35:18
被覆盖 —— 此后无任何新 exthost 启动,故现场锚仍是**旧文案 + 未过滤脏行**。

处置:`Ctrl+Shift+P` → **Developer: Reload Window**。

### 生效范围(重载后)
- **A/B(锚文案)**:重载即生效,同一会话的下一轮锚即为新文案。
- **C(注入侧过滤)**:重载即生效,且**对同一会话的锚立即起作用** —— 因为
  `mapLinesRaw = sanitizeMapLines(getResidentMap())` 在**每次注入时**执行,
  不过滤已落盘的压缩块,而是过滤「投递出去的那一份」。
- **仍需新会话的情形**:旧会话的历史消息里已累积大量复述句(assistant 正文),
  模型可能继续模仿其语域。若要彻底断掉模仿,才需新会话;仅看锚尾部是否干净,
  重载后同一会话即可验证。
