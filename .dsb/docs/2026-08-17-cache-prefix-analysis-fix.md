# 缓存前缀分析脚本修复与命中率口径修正(2026-08-17)

> 生成时间:2026-08-17
> 范围:`scripts/analyze-cache-prefix.py` 的三项修复 + 真实命中率口径修正。
> 结论预览:稳定期 **97.0~97.7%**;压缩后首轮 **49~54%**(此前误报 89.6%)。

---

## 一、背景

08-16 基线文档(`2026-08-16-P2落地后缓存命中新基线.md`)声称:
稳定期 96.8%、压缩后首轮 89.6%("雪崩根治")。
其中压缩后首轮 89.6% 来自脚本的「compaction 后 30s 内所有 round」口径,
把压缩后**已恢复命中**的轮次一并计入首轮 → 虚高。

同时脚本存在 sendSeq 排序/归组缺陷,导致估算口径严重失真
(08-16 估算 46.5% vs 真实 95.0%)。

## 二、脚本三项修复

### 修复 1:sendSeq 排序与配对

- **原缺陷**:`rows.sort(key=lambda r: (r[0], r[1]))` 按 (seq, t) 排序。
  同一 sessionId 因 `createSession` 重建(08-16 有 8 次)出现同 seq 多轮、
  多时间线交错 → 把重建前后的独立请求误配为「相邻轮」→ 272 对全判断裂。
- **修复**:按 `(t, seq)` 时间序排序;`seq <= prev_seq` 视为会话重建,跳过配对
  仅更新 prev(防止同周期内 seq 回退误配)。
- **效果**:可判定相邻对 272 → **924**(08-16);断裂轮 272 → **91**。

### 修复 2:归组丢失 miss

- **原缺陷**:compacted 近似(h=min(prev,cur))归组时,hit 分摊后剩余 miss
  没有按块计入 → compacted 组 miss 恒为 0。
- **修复**:归组循环保证 `hit+miss = cur 块总 tokens`,逐块分摊。
- **效果**:08-16 compacted miss 0(近似下旧块全命中,增量微小),tail miss 1.29M,
  估算 96.0% vs 真实 95.0%,高度吻合。

### 修复 3:broken 语义与块级追加

- **原缺陷**:
  - 尾部追加(新消息/新块)被计入 broken(前缀断裂);
  - `compare_message` 无法区分「块扩展(cur 以 prev 为前缀)」与「块变化」。
- **修复**:
  - `compare_message` 返回 `(hit, miss, is_extend)`;`is_extend` = cur 以 prev
    为前缀且更长 → 前缀未断,仅新增块 miss;
  - `broken` 只统计**既有消息内容变化**(首块/中部块不同、index 序列不匹配);
  - 尾部新增消息(在 prev 消息数之后)只计 miss 不计 broken。
- **验证**:`--self-test` 六场景合成数据全绿
  (append 不裂 / 压缩轮近似 / 块插入断裂 / 块追加不裂 / seq 重置跳过 / 稳定期多轮)。

## 三、真实口径修正(权威结论)

脚本真实口径改为:**压缩后首轮 = compaction 完成后的第一个 provider_round**。

| 日期 | 压缩次数 | 压缩后首轮 | 稳定期 | 总命中率 |
|---|---|---|---|---|
| 08-15(3 会话) | 175 | **49.1%**(95 轮) | 97.0% | 93.3% |
| 08-16(1 会话,959 轮) | 132 | **54.4%**(66 轮) | 97.7% | 95.0% |

**解读**:

1. **稳定期 97.0~97.7%** —— 正确且显著(旧基线 68~75%,+22~29pp)。✓
2. **压缩后首轮 49~54%** —— 相对旧基线 ~10% 提升 +40pp,但**未完全根治**:
   - 命中部分 = system + tools + **compacted 旧块**(P2 只追加不重写生效);
   - miss 部分 = 压缩后 tail 全部新消息(结构性成本)+ compacted 增量;
   - 旧「30s 窗口」口径把后续已恢复命中的轮次计入 → 虚高 89.6%,已废弃。
3. **雪崩成本**:每次压缩轮 miss ≈ 22K tokens(≈¥0.022),主要是 tail 重建成本。

