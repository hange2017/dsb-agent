## 二、估算口径(方案 B,相邻轮 hash 对比)——偏悲观,仅供参考

| 分组 | 命中 | 未命中 | 命中率 |
|---|---|---|---|
| tail | 11,510,947 | 6,378,921 | 64.3% |
| compacted | 13,057,220 | 5,085,978 | 72.0% |
| 合计 | 24,568,167 | 11,464,899 | 68.2% |

- 压缩雪崩轮(compacted 前缀断裂):288 轮 / 5.09M tokens(估算口径)。
- **08-15 估算 93.3% = 真实 93.3%,完全一致**(该日无 seq 重置干扰,估算可信):
  - compacted 98.4%、tail 88.1%。
- **08-16 估算 46.5% vs 真实 95.0%,严重失真**(见下节)。

### 估算为何在 08-16 失真

1. **sendSeq 重置误配(bug,已修复)**:08-16 会话有 8 次会话重建(sendSeq 从 332→1 等),
   脚本原先把重建前后的独立请求误配为"相邻轮",误报 725/827 轮在 0-10% 断裂。
   修复:seq 回退/相等视为会话重建,跳过配对。修正后断裂 426/1075 对。
2. **消息粒度 vs 按块落盘**:compacted 块位于消息列表 index 0,估算按"整条消息全有全无"
   把压缩后整轮判 miss(该轮 tail 0% 命中);真实 API 按块落盘,compacted 块变化
   只影响该块(≈18K tokens/次),tail 大多仍命中。
   08-16 真实未命中 2.23M ≈ 118 次压缩 × ~18K = 2.05M,与估算的 compacted 断裂吻合,
   tail 实际未命中仅 ~0.18M。

**方法论修正:一切结论以真实口径(provider_round)为准;估算口径仅用于归因与预警。**
