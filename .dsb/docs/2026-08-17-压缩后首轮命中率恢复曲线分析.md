# 压缩后首轮命中率 · 恢复曲线分析

> 生成时间：2026-08-17
> 数据：`~/.dsb/stats/3d1dff85bb2f/events-2026-08-15.jsonl` + `events-2026-08-16.jsonl`（真实 provider_round 口径，184 次压缩事件）
> 工具：`scripts/analyze-cache-prefix.py`（已支持「压缩后第 k 轮」分组输出，`--self-test` 7 场景全绿）

## 问题

压缩后首轮命中率只有 49~54%，看起来像「压缩把缓存打崩了」。这是压缩方式的缺陷，还是结构性成本？

## 结论：结构性一次性成本，第 2 轮即完全恢复

| 分组（真实口径） | 轮数 | 命中率 |
|---|---|---|
| 压缩后第 1 轮（最差） | 91 | **54.8%** |
| 压缩后第 2 轮 | 90 | **97.1%** |
| 压缩后第 3 轮 | 90 | 96.4% |
| 其余轮（稳定期，4+） | 1123 | 98.1% |

**恢复速度 = 1 轮**：第 2 轮请求前缀与第 1 轮完全相同 → compacted + tail 全部命中。所谓「雪崩」是**每次压缩的一次性成本**，不是持续劣化。

## 断裂点定位（字节级 hash 对比）

对 184 次压缩事件，逐块对比「压缩前最后 send」与「压缩后首轮 send」的 messageBreakdown hash：

- **compacted（index 0）：hash 100% 相同 → 全部命中（平均 17,997 tokens/轮）**
  - P2「压缩块只追加不重写」在真实请求中生效：压缩后 compacted 旧块字节不变，直接命中缓存前缀。
- **index 1 起（tail 全部）：hash 全不同 → 全 miss（平均 ~13.7K tokens/轮）**
  - 原因：压缩折叠中间历史后，tail 消息的**前缀位置前移**（前面少了中间消息），字节流整体变化 → 即使 tail 内容未变也无法命中。
  - 这是**任何压缩方案的结构性代价**：压缩的本质就是删除中间内容、改变后续消息位置。

## 首轮 miss 构成（平均值）

```
总输入 48,803 = system+tools(~17.2K) + compacted(18.0K) + tail(13.7K)
命中 26,738   = system+tools(部分) + compacted(全命中)
未命中 22,065 ≈ tail 全 miss(13.7K) + system/tools 变化部分(~8.4K*)
```
（*估算口径与真实口径混算的系统偏差 + 会话重建/首次压缩时 system+tools 未完全命中；`provider_send` 为估算值、`provider_round` 为真实值，±30% 误差内。）

## 雪崩首轮（<20%）只有 6/184 次

多为 **sendSeq=1 的会话首轮**（会话重建/首次压缩）：compacted 块全新生成 → 无旧块可命中，命中仅剩 system+tools 的稳定部分（最低 7.6%）。这是**首次压缩的固有成本**，与压缩实现无关。

## 收益核算（为何值得）

- 一次性成本：每次压缩 ≈ 22K tokens 未命中。
- 收益：压缩后每轮只需发送 compacted(18K)+tail(13.7K)+system/tools(17K) ≈ 49K；不压缩则每轮发送全部历史（压缩前最后 send 平均 132 个块 vs 压缩后 69 个块）。
- 08-15/16 期间压缩间隔约 7~10 轮，收益 >> 成本；稳定期 98.1% 命中率证明压缩后长期成本极低。

## 与估算口径对账

- 估算 miss（消息部分）1.40M vs 真实 miss 2.73M：差 1.33M ≈ system+tools 部分的未命中（每轮 ~1.4K，主要来自会话重建/首次压缩的少量轮次 + 估算偏差）。
- 估算口径「compacted 近似命中、miss 仅为增量」与真实一致：compacted 字节稳定（hash 相同）→ 真实全命中。

## 后续优化方向（可选）

首轮成本已最小化（compacted 稳定 + tail 只删尾部）。若要进一步压缩首轮 miss，可行方向：

1. **tail 也进 compacted**（全部折叠）：首轮 miss 只剩 compacted 增量，但会牺牲模型可读的近期细节，且折叠本身有成本。**不推荐**。
2. **减少压缩频率**（提高 triggerRatio / 预算）：摊薄一次性成本。当前 ~7-10 轮一次已是合理区间。
3. **恢复期加速**：首轮后可考虑「压缩后第 2 轮强制预热」——实际上第 2 轮天然全命中（前缀相同），无需干预。
