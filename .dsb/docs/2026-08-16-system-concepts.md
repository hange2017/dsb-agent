## 概念 1:一次「对话轮」(send)= 多轮「模型往返」(round)

### 一句话

用户点一次「发送」到蓝色输出框出现,是一次 **对话轮(send)**;这期间 agent 与模型内部发生了 **多轮 round 的往返**——每轮都是「把全部历史发给模型 → 模型生成回复 →(若要工具)执行工具再进入下一轮」。

### 分层术语表

| 术语 | 层级 | 定义 | 代码位置 |
|---|---|---|---|
| **send / 对话轮** | UI / 会话层 | 用户一次输入(蓝色输入框)→ agent 最终回复(蓝色输出框)的完整交互 | `src/agent/agentLoop.ts:494` `send()` |
| **round / 模型往返** | 引擎层 | 一次「把全部历史 messages 发给模型 → 模型生成一段回复」的往返;回复可能是文本,也可能是「请求执行工具」 | `agentLoop.ts:532` `for (let round = 0; round < maxRounds; round++)` |
| **工具执行** | 引擎层 | round 内模型请求工具后,agent 本地执行该工具(Bash / 写文件 / 读文件…),结果以 tool_result 放回历史 | `agentLoop.ts:699-775` |
| **terminal / 终态** | 引擎层 | 某一 round 模型输出纯文本且无工具请求(或 blocks 为空)→ 该轮即最后轮,send 结束 | `agentLoop.ts:683-689` |
| **时间线动作** | UI 层 | 蓝色输出框里的中间过程步骤(各轮执行的工具),可折叠 | `webview/main.ts` `timeline` / `collapseLastRoundIntermediates` |

### 生命周期(一次 send 内部)

```
用户点击发送
   │
   ▼
round 0: 全部历史 → 模型 → 回复「要执行 Bash」 ──┐
   │  agent 执行 Bash,结果入历史                    │ 往复
   ▼                                              │ 直到……
round 1: 全部历史(+Bash 结果) → 模型 → 回复「要改文件」 │
   │  agent 改文件,结果入历史                       │
   ▼                                              │
round 2: 全部历史 → 模型 → 回复纯文本(不再要工具) ──┘
   │
   ▼
send 结束 → UI 渲染蓝色输出框
```

- 每轮发送的「全部历史」包含:之前所有轮的用户消息、assistant 回复、工具结果、thinking、压缩块等。
- `maxRounds` 默认 `1_000_000`(`agentLoop.ts:71`),理论无上限,由上下文窗口与压缩兜底。
- 同一轮模型可请求**多个工具**(并行,`toolUses` 数组),全部执行完才进入下一轮。

### UI 层「轮次」与引擎层「round」的区别(易混淆)

- **UI 层「轮次」**(`webview/main.ts:251` `splitHistoryRounds`):**每轮 = 一条用户消息 + 其后的 assistant 事件**(蓝色输入框 + 蓝色输出框)。▲▼ 轮次导航(2026-08-16 实现)按此切分。
- **引擎层「round」**:一次 send 内部模型往返的次数,用户不可见(只见时间线动作)。
- 对应关系:**UI 一轮 ≈ 引擎多次 round**。一个蓝色输出框内部的所有时间线步骤,就是这多次 round 各自执行的工具。

### 与取消(abort)的关系

- `AbortController` 只支持**取消**:取消 = 回滚本轮尚未完成的改动并结束 send(`agentLoop.ts:536,620`),**没有**「运行中注入新消息」的通道。
- 取消是正常操作,静默返回,不发 error 事件;已完成的轮次保留在历史中。
