# 统计复现指南(跨机器 · Windows / Linux)

> 目的:把「压缩预算/命中率/每轮成本」的分析做成**任何一台机器都能一字不差重跑**的流程,
> 便于在公司 Linux 机器上做同日对照(用户诉求:`明年去公司后做同样的分析,方便后面有使用记录后对比`)。
> 触发:2026-09-19 会话末尾,`analyze-budget-windows.py` 增加「项目自动探测 + 窗口过滤 + 报告落仓库」后固化本流程。

## 一、数据从哪来

Agent 运行时把原始事件写成本地 JSONL:

```text
~/.dsb/stats/<projectKey>/events-YYYY-MM-DD.jsonl
  Windows: C:\Users\<用户>\.dsb\stats\<projectKey>\
  Linux:   /home/<用户>/.dsb/stats/<projectKey>/
```

每个文件是**当天**的事件流(按项目隔离,默认保留最近 N 天)。两条分析脚本都**直接读这里**,不依赖 VS Code 是否在跑。

### 关键概念:projectKey 不等于项目名

`projectKey` 由 `src/agent/projectScope.ts` 计算,规则(优先级从高到低):

1. **有 git remote origin** → `sha1(normalizeRemoteUrl(url)).slice(0,12)`(12 位十六进制)。
   - 归一化:去协议/用户信息/尾部 `.git`/大小写,`git@host:path` 的冒号转斜杠。
   - ⇒ **同一仓库的不同 worktree、不同机器、不同目录**,只要 remote 相同,`projectKey` 就相同 → 数据落在同一个目录里,可直接对比。
2. **无 git / 读不到 remote**(fail-open) → 工作区路径 slug:
   `root.toLowerCase().replace(/[^a-z0-9]+/g,"-").replace(/^-+|-+$/g,"")`。
   - 例:`E:\DSB\dsb-agent` → **`e-dsbagent`**;`C:\Users\91441\Desktop` → **`c-users-91441-desktop`**。
   - ⚠️ **注意**:本机当前主项目的数据落在 **`e-dsb`**(不是 `e-dsbagent`),说明它是按工作区根 `E:\DSB` 的 slug 落的(该根目录当时无 git remote)。
     **两台机器的目录名可能不同**,所以脚本默认**自动探测事件最多的项目**,不要硬编码项目名。

> 结论:跨机器对比时,**不要假设目录名一致**;先 `--list` 看探测结果,必要时用 `--project <目录名>` 指定。

## 二、两个脚本

仓库 `scripts/` 下(纯标准库,无第三方依赖,Python ≥ 3.8 即可):

| 脚本 | 作用 | 默认输出 |
|---|---|---|
| `scripts/analyze-budget-windows.py` | 三档预算(64k/96k/30k)窗口对比:**压缩频率、压缩后命中率、每轮成本** | 仓库 `.dsb/docs/budget-windows-report.txt` |
| `scripts/analyze-round-efficiency.py` | 按「日 × 项目」看:**每轮成本、压缩次数、命中率、配置变更时间线** | 终端 |

### 通用约定

- **stats 根目录固定为 `~/.dsb/stats`**(脚本内 `os.path.expanduser("~")`),Windows/Linux 自动适配。
- **project 默认自动探测**:取 stats 下**事件数最多**的目录;`--project` 可显式指定。
- **命中率口径**:`cacheRead / (cacheRead + input)`(与 `turn_summary.cacheHitRate` 一致)。
- **压缩批次**:60s 内的 `compaction` 事件合并为 1 批(一次压缩会 emit 多条轨道事件)。
- **输出编码统一 UTF-8 + LF**(`newline="\n"`),保证两端报告可逐行 diff。

### analyze-budget-windows.py 参数

```text
--project PROJECT   stats 下的项目目录名;默认自动探测
--out OUT           输出文件;默认写仓库 .dsb/docs/budget-windows-report.txt
--window WINDOW     只算名称含该子串的窗口(可重复,如 --window 30k)
--list              只列出窗口定义与自动探测到的项目
--stdout            同时在终端打印报告
```

内置窗口(绝对时间,换机器后本机无对应日期会自动标注「无数据」而不是报错):

| 档 | 配置(预算 / 块:tail / 触发) | 时间窗 |
|---|---|---|
| 【A】 | 64000 / 0.56:0.44 / 0.75 | 2026-09-14 21:26 ~ 23:03 |
| 【B】 | 96000 / 0.30:0.70 / 0.75 | 09-14 23:03 ~ 09-15 00:00 |
| 【B2】 | 同上 | 09-15 整日 |
| 【B3】 | 96k 时代合计 | 09-14 23:03 ~ 09-18 00:00(含 09-15、09-17) |
| 【C】 | 30000 / 0.20:0.80 / 0.85 | 09-19 21:48 ~ 09-20 00:00 |
| 【C2】 | 同上 | 09-20 00:00 ~ 00:40 |
| 【C3】 | 30k 合计 | 09-19 21:48 ~ 09-20 00:40 |

新增对比窗口:在脚本 `WINDOWS` 常量加一行 `(名称, 起, 止)` 即可。

### analyze-round-efficiency.py 参数

```text
--project e-dsb                      只看某项目
--dates 2026-09-15 2026-09-19        限定日期(可多个)
--config                             只打印配置变更时间线(settings_change)
--files <path...>                    直接指定 jsonl 文件
```

## 三、Linux 上怎么跑

```bash
# 0) 仓库(假定已在 Linux 机器上 clone 过)
cd /path/to/dsb-agent

# 1) 环境:Python 3.8+ 即可,无第三方依赖
python3 --version

# 2) 先看有哪些项目和窗口(不改动任何文件)
python3 scripts/analyze-budget-windows.py --list

# 3) 生成完整报告(默认写到仓库 .dsb/docs/budget-windows-report.txt)
python3 scripts/analyze-budget-windows.py

# 3b) 只跑 30k 档,并同时看终端输出
python3 scripts/analyze-budget-windows.py --window 30k --stdout

# 3c) 若自动探测选错项目,显式指定
python3 scripts/analyze-budget-windows.py --project e-dsbagent

# 4) 配置变更时间线(核对两台机的默认值改动是否一致)
python3 scripts/analyze-round-efficiency.py --config
```

Windows(PowerShell / cmd,本机 `py` 或 `python` 均可):

```powershell
python scripts/analyze-budget-windows.py --list
python scripts/analyze-budget-windows.py --stdout
python scripts/analyze-round-efficiency.py --config
```

> Windows 终端若出现中文乱码,是**控制台代码页**问题(文件本身是 UTF-8);
> 报告以落盘文件为准,或用 `--out report.txt` 另存后再看。

## 四、怎样对比两台机器(操作建议)

1. **先对配置**:跑 `--config`,确认两台机在同一日期段内的 `budget.total / split / triggerPct` 一致。
   不一致时,报告里的「预算档自动识别」小节会列出本机实际生效过的档位,据此判断可比的窗口。
2. **再对结论**:跑 `analyze-budget-windows.py`,比对每档的:
   - `轮/压缩` 与 `每千轮压缩`(压缩频率)
   - `压缩后首轮命中率` / `第 2 轮` / `恢复到 80% 平均轮`(恢复速度)
   - `effIdx/轮` / `$/轮`(每轮成本)
3. **补历史日期**:本机缺 09-16(那天在公司 Linux 机器上做),要把 `/home/<用户>/.dsb/stats/*/events-*.jsonl` 拷回来,
   放到本机同名 `<projectKey>/` 目录下,即可补齐「同日对照」。
   - ⚠️ 拷回时**保持文件名**(`events-YYYY-MM-DD.jsonl`)与**目录名(projectKey)**不变;若两边 projectKey 不同(一台有 git remote、一台没有),
     拷回后需手动改目录名,或临时用 `--project` 指向。
4. **口径一致性**:报告头部会打印 `主机` 与 `python 版本`,便于确认报告来源;两张报告可直接逐行 diff。

## 五、已知边界

- 脚本只读 `~/.dsb/stats`,**不读会话文件**,所以「压缩 QA 可答率」「turn_summary」这类指标依赖对应埋点是否在当天版本里生效;
  旧日期若缺埋点,对应行会缺失或为 0,属正常,不代表配置问题。
- 窗口日期是**绝对时间**;换机器只影响「是否有数据」,不影响统计口径。
- `$ / 轮` 用 DeepSeek 档位近似常量估算,只做**横向比较**,不是账单金额。
