# 压缩摘要调用「空转 thinking」核算与处置(T5)

> 生成时间:2026-09-15
> 触发:§8.4 附带发现("压缩摘要调用在为空转 thinking 付费")的落地核算
> 口径:全库 22 个 stats 文件,`provider_round{phase:"compact"}` 对比 `phase!=compact`
> 单价(与 `scripts/analyze-cache-prefix.py` 一致):输入 ¥1.0 / 缓存读 ¥0.02 / 输出 ¥2.0(每百万 tok)
> 结论:**该现象真实存在,但定性不是「浪费」而是「回归」——`a5c857a` 移除全局 thinking 总闸时,连带删掉了
> `withThinkingDisabled` 包装,使压缩调用重新带上模型侧 thinking 预算。修复点一处即可同时消除
> 「空转付费」与「协议违规 400 风险」。**

## 一、结论摘要

| 项 | 结论 |
|---|---|
| 现象 | 压缩摘要调用确实在产出**不被采用**的 thinking 输出并付费 |
| 定性 | **回归**,非新设计缺陷:`1ea650a` 的总闸曾隐式屏蔽;`a5c857a` 移除总闸时丢失该行为 |
| 根因 | `prepareRound` 按 `caps.thinkingLevel` 派生 budget(medium=4096),**完全不感知调用方 maxTokens** |
| 叠加隐患 🔴 | 压缩调用 `maxTokens` 被钳到 800/200/3500,而 budget 仍 4096 → **`budget_tokens >= max_tokens`,违反 Anthropic 硬约束**;失败被 `catch` 静默降级为兜底文案 |
| 用户侧误导 🔴 | settings 仍留有 **死键** `dsbAgent.thinking.enabled=false`(已在 `a5c857a` 从 package.json 移除,无人读取),用户以为已关 thinking,实际全链路已重开 |
| 金额 | 压缩成本 ¥0.647(占总额 ¥53.28 的 **1.21%**);其中未被采用输出 51,428 tok = **¥0.10 = 总支出 0.19%** |
| 优先级 | 金额极小,但**协议违规 + 静默降级**属正确性风险,应按 P0 处置 |

## 四、叠加隐患(比金额重要)

### 4.1 🔴 协议违规:违反 `budget_tokens < max_tokens`

- Anthropic 扩展思考硬约束:`budget_tokens` 必须**小于** `max_tokens`。
- 压缩三类调用全部违规:

| 用途 | 调用方 maxTokens | 透传 budget | 合法? |
|---|---|---|---|
| explanation | 800 | 4096 | ❌ |
| resummarize | 200(=800/4) | 4096 | ❌ |
| thinking 轨 | 3500 | 4096 | ❌ |
| (对照)主对话 | 8192 | 4096 | ✅ |

- 当前 DeepSeek 兼容端点**宽容接受**了该组合,但这是**端点实现细节**,不是协议保证。
- 换成严格实现(原生 Anthropic、或未来端点收紧校验)→ **400**。

### 4.2 🔴 静默降级:400 会被吞掉,压缩块变空

- `summarizeMessages` 全函数 `try/catch`,**catch 返回 `FALLBACK_SUMMARY = "已省略前文对话。"`**。
- 后果链:压缩 LLM 调用 400 → 兜底 → **压缩块内容为空**(需求/结论/说明全丢)→ agent 失去任务地图与历史结论
  → 重复劳动、跑错任务(与用户反馈的"信息丢失导致重复做事"同源)。
- **本轮核查:未发现真实降级**。全库搜到 63 处 `已省略前文对话` 文本,
  逐处核对**全部是源码/文档里的常量定义**(`const FALLBACK_SUMMARY = "已省略前文对话。"`)
  出现在被 Read/Grep 的履历里,**不是失败的压缩块**。`compaction` 事件中 `usedLLM=true` 274 次,
  **无一次** `llmCalls>0 && selfOutputTokens=0`。
- 即:风险真实、当前未爆。

### 4.3 🔴 用户侧误导:`dsbAgent.thinking.enabled=false` 是死键

- 用户 settings 现存:`"dsbAgent.thinking.enabled": false`、`"dsbAgent.compaction.thinking": false`。
- `package.json` 的 `contributes.configuration` 中**已无** `dsbAgent.thinking.enabled`
  (现存 thinking 相关键只有 `dsbAgent.compaction.thinking`)。
- 全库源码**无任何读取点**;`git log -S` 确认该键由 `1ea650a` 引入、`a5c857a` 移除。
- 语义差异(易误解):

| 键 | 真实作用 | 不做什么 |
|---|---|---|
| ~~`dsbAgent.thinking.enabled`~~(已移除) | —— | —— |
| `dsbAgent.compaction.thinking`(现存) | 处理侧:关闭后**剥离**产出 thinking(不进历史/压缩/脉络) | **不阻止模型侧产出**;请求仍带 budget |

- 即:用户把 `compaction.thinking=false` 理解为"关思考",实际是
  **"模型照常思考并付费 → 产出被丢弃"**。代码注释亦明说:
  「模型可先思考(请求仍带预算),但流程不处理 thinking」。

## 五、处置方案

### 5.1 P0(已实施):按 maxTokens 约束解析 thinking,一处修复消除 4.1 + 4.2

**规则(协议自洽 + 保证正文有额度)**:

> ① 预算 + 正文预留能装进本轮 `max_tokens` → 原样启用;
> ② 装不下 → **收敛**为 `maxTokens - 1024`(把多余额度还给正文,而不是让思考吃光输出);
> ③ 收敛后低于协议下限 1024 → **禁用**(绝不发 `budget_tokens >= max_tokens` 的违规组合)。

> 备注:规则曾是「装不下即禁用」,实现时发现会误伤 `high` 档(16384 配 8192 输出 → 直接失去思考),
> 故改为「先收敛、只有连 1024 都容不下才禁用」,兼顾协议自洽与推理能力保留。

- 落点 `capabilityGate.ts` 新增解析函数,统一产出 `{ thinkingBudgetTokens?, thinkingDisabled? }`:

```
kMinThinkingBudgetTokens = 1024        // 协议下限:budget_tokens >= 1024
kThinkingOutputReserveTokens = 1024    // 启用思考时为正文保留的最小输出额度

resolveThinkingParams(caps, maxTokens, opts?):
  if caps.supportsThinking !== true            -> { thinkingDisabled: true }
  if 调用方显式 opts.thinkingDisabled === true -> { thinkingDisabled: true }
  budget = effectiveThinkingBudgetTokens(caps)
  if budget === undefined                      -> {}
  if budget + 1024 <= maxTokens                -> { thinkingBudgetTokens: budget }  // ① 原样
  fit = maxTokens - 1024
  if fit >= 1024                               -> { thinkingBudgetTokens: fit }     // ② 收敛
  else                                         -> { thinkingDisabled: true }        // ③ 禁用
```

- 主对话不受影响:`maxTokens=8192`、`medium=4096` → `4096+1024 <= 8192` → 仍启用(行为不变)。
- 压缩摘要:explanation 800 / resummarize 200 → 落入 ③ 禁用;thinking 轨 3500 → 落入 ②
  收敛为 2476(保留必要推理,不再吃掉几乎全部输出额度)。
- 调用方落点:`agentLoop.summarizeMessages` 按**钳后的 maxTokens** 重解析;主对话轮与
  `fallbackClient` 补齐 `prepared.thinkingDisabled` 传播;`anthropicMessagesClient` 再做
  协议纵深防御(`budget >= maxTokens` 一律降级 disabled)。
- **不需要** `requiresThinking` 能力位:本规则**不假设**端点是否接受 `thinking.disabled`
  ——`thinking.disabled` 是 Anthropic 协议既有值,`anthropicMessagesClient` 已在
  `supportsThinking=false` 分支使用并有测试覆盖(`tests/anthropicMessagesClient.test.ts:256/326`)。
  比"猜哪些模型是推理必需"更保守、更可测。

### 5.2 P0(纵深防御):client 层钳制

- `anthropicMessagesClient.round`:在发 `thinking.enabled` 前做兜底校验,
  `budget >= maxTokens` 时**降级为 `disabled`**(而非静默发出违规组合)。
- 理由:`capabilityGate` 是"调用方自律",client 是"协议最后一道门";两者都做,
  未来任何新调用方(插件/其它工具)误传都不会炸。

### 5.3 P1(待用户决策,本次不改代码):死键处置

- 选项 A:从 settings 清理 `dsbAgent.thinking.enabled`(推荐,避免继续误导)。
- 选项 B:恢复该键为真正的"全链路总开关"(即回收 `1ea650a` 语义)。
- 选项 C:新增 `thinkingRequired` 能力位,供纯推理模型豁免禁用。
- **本轮不动**:A 属用户环境清理,B/C 需产品决策;已在本文档登记。

| 项 | 金额/影响 | 性质 |

| 压缩未被采用输出(本文) | ¥0.10(总支出 0.19%) | 成本效率 |
